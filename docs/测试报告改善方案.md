# 测试报告改善方案

来源：`D:\DESKTOP\RiskLendPro测试报告.md`（基线 `7560ead`，2026-10-08）。
范围：只处理报告里已复现、并且会挡住使用的问题。产品规则（直接借款利率、客服未做完）不在这次改。

单测 50 个全部通过，不能说明这些缺陷不存在：失败点都在「更新产品」「读产品详情」「异常出口」，现有单测没有覆盖。

## 先改什么

| 顺序 | 编号 | 现象 | 改动 |
|---|---|---|---|
| 1 | H1 | 更新产品、上下架、新建/启停机构全部失败 | 升级 MyBatis-Plus，保留乐观锁 |
| 2 | H2 | 已上架产品的详情接口恒定 400 | 缓存前把日期写成字符串，并修正 Redis 序列化 |
| 3 | M1 / L3 | 缺参数返回 500，空请求体和 SQL 异常把内部信息回给前端 | 收紧全局异常处理，补分页默认值 |
| 4 | M3 | 审批邮件失败会把本地事务回滚，额度已经发出去 | 邮件放到事务提交之后 |
| 5 | 图片 403 | 产品图链接匿名打开是 403 | 在没有自定义域名之前，用签名读链接 |

下面每项都写了改哪里、怎么改、怎么验收。

## 1. H1：产品 / 机构更新全部失败

管理端这些接口稳定失败：

- `POST /api/v1/admin/products/institutions`（新建机构）
- `PUT /api/v1/admin/products/{id}`（更新产品）
- `POST /api/v1/admin/products/shelf`（上下架）
- `POST /api/v1/admin/products/institutions/{id}/enabled`（启停机构）

报错是 `Parameter 'MP_OPTLOCK_VERSION_ORIGINAL' not found. Available parameters are [param1, et]`。新增产品、删除草稿不走 `updateById`，所以测试里那两条是成功的。

原因：`services/common-runtime/pom.xml` 里 MyBatis-Plus 停在 `3.5.5`。Spring Boot 3.5 带的 MyBatis 已经不再把乐观锁插件写入的版本参数暴露成这个名字，`OptimisticLockerInnerInterceptor` 每次 `updateById` 都会失败。这是 Java 参数绑定问题，换到线上 MySQL 一样会失败。带 `@Version` 的实体是 `LoanProduct` 和 `LoanInstitution`。

改法：

1. 把 `mybatis-plus-spring-boot3-starter` 从 `3.5.5` 升到 `3.5.12`（3.5.9 及以上即可，3.5.12 和当前 Spring Boot 3.5 配套）。只改这一个版本号，拦截器注册顺序不用动：先乐观锁，再分页。
2. 不要删 `@Version`。乐观锁本身是对的，删掉只是把冲突检测也一起丢掉。
3. 升完后跑一遍 `mvn -pl services/loan-service -am test`，再手工打上面四个接口。

验收：更新产品、上架、新建机构、启停机构都返回成功；故意用旧 `version` 再更新一次，应得到「数据已被他人修改」这类提示，而不是 500。

L3（更新失败时 `message` 为空）会跟着消失。乐观锁异常现在被 `GlobalExceptionHandler` 当成普通 `RuntimeException`，外层 message 经常是 null。H1 修好后，剩下的异常文案由第 3 节统一处理。

## 2. H2：已上架产品详情打不开

`GET /api/v1/loan/products/{id}` 在产品有 `verified_at` 时返回 400：

`Could not write JSON: Type id handling not implemented for type java.lang.Object (... meta.verifiedAt)`

上架校验要求 `verifiedAt` 非空，所以所有合规上架产品的详情都会失败。列表接口不缓存这条详情，所以列表是正常的。

原因不在 HTTP 的 Jackson，而在写入 Redis 的那一步。`LoanCatalogService.userDetail` 把详情 Map 放进 `CatalogCache`，序列化器是 `RedisConfig` 里无参构造的 `GenericJackson2JsonRedisSerializer`。它开启了默认类型信息，Map 里的 `LocalDate` 写不进去。`verifiedAt` 为空时 Map 里没有这个日期，所以又能成功。

`CatalogAssembler` 第 124 行把 `verifiedAt` 原样放进 `meta`。同文件里导出知识库已经改成 `toString()`，详情这条漏了。只给 Redis 的 ObjectMapper 注册 `JavaTimeModule` 往往还不够：默认类型信息和 `LocalDate` 序列化器不兼容，仍会报 type id。

改法分两层，都要做：

1. `CatalogAssembler` 组装详情时，`verifiedAt` 改成和 `updateTime` 一样的字符串（`null` 就放 `null`）。这样缓存内容里不再出现 `java.time`。
2. `RedisConfig` 改用自己构造的 `ObjectMapper`：注册 `JavaTimeModule`，日期写成 ISO 字符串，再交给 `GenericJackson2JsonRedisSerializer`。避免以后别的缓存再踩同一个坑。

验收：找一条 `verified_at` 非空且已上架的产品，连续请求详情两次，两次都是 200，第二次命中缓存仍是 200。Redis 里能看到 `catalog:product:{id}`。

## 3. M1：错误响应泄露内部信息，缺参数却返回 500

`GlobalExceptionHandler` 现在的行为：

- 所有 `RuntimeException` 都把 `e.getMessage()` 放进 `body.code=400`，HTTP 仍是 200。
- 其他 `Exception` 一律 `body.code=500`、文案「服务器内部错误」，HTTP 仍是 200。

因此出现这些结果：

| 请求 | 实际 | 应该 |
|---|---|---|
| 产品列表不传 `pageNum` / `pageSize` | body 500 | 使用默认分页，或 400 提示缺分页 |
| `POST /auth/register` 空 body | 回显 `UserRegisterRequest.getPassword()` 的空指针 | 400，提示请求体不合法 |
| 调额缺 `newLimit` | 回显 `BigDecimal.compareTo` | 400，提示缺额度 |
| 并发借款失败的那一笔 | 回显 SQL、Mapper 路径、表名 | 固定文案「服务器内部错误」，详情只写日志 |
| 不存在的路径 | body 500 | 404 |

产品列表失败，是因为 `UserLoanProductController`、`AdminLoanProductController` 的 `pageNum` / `pageSize` 是必填，没有默认值。用户借款记录那几个接口已经有 `defaultValue`。缺参数抛出的是 `MissingServletRequestParameterException`，它不是 `RuntimeException`，所以落到了 500 那个分支。

改法：

1. 产品列表、机构列表的分页参数改成和其他列表一样：默认第 1 页、每页 10 条，并继续拒绝 `pageSize > 50`。
2. 注册、登录、调额等入参加上 `@Valid`。空 body、缺字段、两次密码不一致，都在进业务方法之前返回 400。
3. 全局异常按类型分开，对外不返回异常原文：
   - 参数缺失、JSON 读失败、校验失败：业务码 400，中文说明。
   - 找不到接口：业务码 404。
   - `DataAccessException`、空指针，以及其他未预期异常：业务码 500，固定文案「服务器内部错误」，完整堆栈只打日志。
4. 业务上打算给用户看的句子，改成单独的业务异常（现有的 `CatalogBusinessException`、`DuplicateApplyException` 就是这个模式），不要再把任意 `RuntimeException` 的 message 直接返回。

验收：用报告里的五个请求再打一遍。响应里不能出现类名、`java.`、`Mapper`、SQL、表名。

## 4. M3：审批通过后，邮件失败会造成额度已发、评估未终审

`AdminRiskQueryServiceImpl.approveRisk` 标了 `@Transactional`，方法末尾才发邮件。邮件抛错时，本地 `risk_assessment` 回滚，但前面已经通过 Feign 调过 loan-service 授信和 user-service 改评估状态，那两次写入各自提交了。测试里关掉真实 SMTP 就能稳定复现：用户已是终审通过、额度已有，评估单仍是人工复核。

改法：邮件挪到事务提交之后。本地评估单更新成功再发；发送失败只记日志，不把审批打回去。可以用事务同步的 `afterCommit`，或单独的异步发送。

跨服务调用本身仍没有补偿：如果授信成功、本地更新失败，还会不一致。这次只先去掉「邮件把已成功的审批打回」这一条。完整的补偿或发件箱留到后面。

验收：让邮件发送抛错，再审批一笔。评估单、用户评估状态、额度三条必须一致，接口按「审批已完成、通知发送失败」处理，不能回滚额度。

## 5. 产品图片链接 403

上传链路是通的：预签名 PUT、直传 COS、confirm 都返回 200。confirm 之后的访问地址匿名 GET 是 403。

报告建议把 `storage.private-bucket` 改回 `true`，并认为桶实际是私有的。这个判断需要修正。桶在控制台是「公有读私有写」，配置里 `private-bucket: false` 也是按这个选的。2024 年之后新建的桶，即使用默认域名做公有读，匿名访问仍会 403，腾讯云要求改走自定义域名。当前没有已备案域名，`cdn-domain` 也是空的，所以公有读直链现在打不开。

在绑定自定义域名之前，把 `config/local/application-local.yml` 的 `private-bucket` 设为 `true`。`CosStorageService.accessUrl` 会改发带时效的 GET 签名，默认域名可以打开。`app-id`、`cdn-domain` 继续留空。

这是本地配置，不要提交进仓库。有了自定义域名之后，再把 `private-bucket` 改回 `false`，并填写 `cdn-domain`。

另外删掉测试留在真实桶里的对象：`loan/cover/202610/764a10f2-588d-4f1a-a661-cf236012ab3d.png`。另一条 `loan_image` 只做了 presign、没有实际上传，不用删对象。

验收：后台产品封面能显示，浏览器直接打开接口返回的图片地址是 200。

## 6. M2：HTTP 状态与业务码

几乎所有业务错误的 HTTP 状态都是 200，真正的码在 `body.code`。网关和监控无法按 4xx/5xx 统计。

这是接口契约，不是单点 bug。前端如果只看 `body.code`，突然改成 HTTP 400 会把现有错误处理打乱。建议和第 3 节一起做，但单独评审：

- `body.code` 保持现状，前端不用改解析。
- HTTP 状态与业务码对齐：参数和业务拒绝用 400，无权限用 403（这个已经是 403），不存在用 404，未预期错误用 500。
- 成功仍是 HTTP 200。

没有前端配合之前，不要只改 HTTP 状态。

## 这次不改

- **直接借款利率 5%（L1）**。不带产品的借款继续用 `DIRECT_RATE`。带产品的借款已经取产品最低年化，测试里 12% 的产品得到 `0.1200`。区间内按风险差别定价是新产品规则，不在这次缺陷里。
- **客服只有 `GET /cs/status`（L2）**。工单和会话还没有控制器，这是未完成功能，不是这次回归。
- **扣子黑名单定时任务、真实 QQ 邮箱、超大文件上传**。报告标明未测，没有失败证据，不凭推测改。
