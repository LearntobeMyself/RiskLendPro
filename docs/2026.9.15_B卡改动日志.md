# RiskLendPro B 卡改动日志

> 变更编号：RISK-BCARD-20260911  
> 记录日期：2026-09-15  
> 变更范围：B 卡基础分、行为分、分数可信度、贷中监控、真实特征快照、历史调额审计  
> 角色说明：刘负责贷中接入、联调、审计、测试和文档；耿协作风险模型与特征服务。

---

## 1. 背景与问题

评估发现现有 B 卡存在以下问题：

1. `recalculate(userId)` 重算时没有传身份证，基础分固定回退为 `700`。
2. 行为调整分没有上下限，线上出现过 `deltaScore=-1007`。
3. 没有还款历史时 `onTimeRate=1`，反而自动增加 40 分。
4. B 卡基础特征通过身份证映射静态 Home Credit 数据，13 个 B 卡用户中只有 4 个能匹配。
5. `watch` 和 `reduce_limit` 由测试集分位直接生成，概率校准和业务阈值不严谨。
6. 每日自动调额会重复乘以当前额度，导致同一用户每日复合降额。
7. 历史已发生 44 次 B 卡自动调额，涉及 5 个用户。
8. 没有真实业务贷后特征快照，也没有可用于训练的观察期/表现期结构。

### 3.3 P0.5：分数可信度控制

```text

```

新增字段：

```text

```

状态值：

```text
RELIABLE
FEATURE_NOT_FOUND
MISSING_ID_CARD
FEATURE_PARSE_ERROR
INSUFFICIENT_HISTORY

```

规则：

1. 基础特征和历史都完整：`scoreReliable=true`。

4. 数据不可信：`limitMultiplier=null`。
5. 自动调额不得使用不可信分数。

```text

```

### 3.5 P1.5：特征质量修正

发现的问题：

1. 多个用户 `tenureDays=8`，但最大 DPD 达到 37 至 345 天。
2. 使用率出现 38.4 的极端值。
3. 用户 108 出现 `currentMaxDpd=90, maxDpd12m=0`。

修正内容：

1. 特征版本升级：

```text
BF_V2.0 → BF_V2.1
```

2. 账龄改为取以下日期的最早业务日期：

```text
贷款申请时间
审批时间
放款时间
计划创建时间
还款记录创建时间
到期日
```

3. 近 12 月最大 DPD 纳入仍在逾期且更新时间在 12 个月内的还款计划。
4. 新增字段：

```text
cappedUtilizationRate
totalLimit
usedLimit
remainingLimit
dataQualityFlags
```

5. 数据质量标记：

```text
UTILIZATION_GT_2
TENURE_LT_MAX_DPD
PLAN_OVERDUE_OUTSIDE_RECORD_WINDOW
```

验证结果：

```text
13/13 用户已生成 BF_V2.1
用户 108 maxDpd12m 从 0 修复为 90
用户 109 maxDpd12m 从 44 修复为 72
用户 63、106 使用率封顶为 2.0
账龄不再小于当前最大 DPD
```
