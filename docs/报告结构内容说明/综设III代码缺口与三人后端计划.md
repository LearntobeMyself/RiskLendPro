## 0. 一句话现状

现在的系统是 **能跑的综设 II 单体**：申请评分、人工审批、借款还款、B 卡调额都有。  
对照综设 III，**微服务、消费贷产品、获客、大模型客服、催收闭环、网关安全、正规测试** 基本还没做。  
管理端还有一批接口是 **内存 Map / 拼装查询**，重启即丢，答辩时经不起追问。

当前组内分工（综设 II）：耿后端、徐 Web、曹 Android、刘/陈文档。  
本学期后端必须变成 **三人**：建议 **耿 / 刘 / 陈** 各领一个服务；徐、曹仍做前端，但只对接三人已发布的接口，不为后端背锅。

## 1. 对照任务书：现在有什么、缺什么

| 任务书项 | 代码现状 | 判定 |
|----------|----------|------|
| 微服务重构 | 单模块 `RiskLendProApplication`，`pom.xml` 无 Gateway/Nacos | **缺，不做连良都没有** |
| 高并发/高性能部署 | Redis 缓存评分报告；无网关限流、无压测工程 | **缺证据** |

| 贷中监控 | 有 B 卡重算、逾期自动调额定时任务、`/admin/b-card/monitor` | **有骨架，缺预警案件与看板闭环** |

| 消费贷 | `LoanRequest` 只有金额/期限/还款方式，无 `productId`，无产品表 | **缺** |
| 获客 | 注册无渠道/邀请码 | **缺** |
| 安全管理 | JWT + BCrypt；`/admin/**` **没有角色校验**；CORS `*`；`/upload/**` 放行；系统配置存在内存 | **有登录，没有真正的安全模块** |

## 2. 三人后端怎么拆（互不覆盖、都能单独演示）

原则：**按微服务切，不按「你写 Controller 我写 Service」切。**  
后者最容易摸鱼（「我在改别人的类」）。每人一个可独立启动的模块，接口契约写在 OpenAPI 里。

建议仓库将来长这样：

```
services/
  gateway/          ← 陈
  user-service/     ← 陈（认证、获客、审计、限流配合）
  risk-service/     ← 耿（评分、黑名单、决策、模型）
  loan-service/     ← 刘（产品、借款、还款、贷中、贷后）
  cs-service/       ← 陈（大模型客服、工单）
risk-assessment/    ← 耿（Python 离线，AUC 底线）
```

前期若来不及五进程，允许 **陈把 user + cs 暂时放同一进程**，但 **gateway、risk、loan 必须三个进程**，否则答辩说不清微服务。

### 2.1 后端甲 · 耿：风控决策服务（`risk-service`）

**为什么给他**：这块代码量最大、和综设 II 连续，换人容易把 AUC 搞崩；优的分数差就在模型效果。

**迁入（已有）**

- `RiskAssessmentController`、补充材料、管理员风控审批  
- `CreditScoreEngine` / `BehaviorScoreEngine`  
- 黑名单 + 扣子同步  
- 征信库只允许本服务访问  

**本学期新做**

1. 决策中枢：规则 → A 卡 → 辅助模型 → 策略表（通过/复核/拒绝/额度档）。  
2. 辅助模型一条链路（XGBoost 等），**只辅助、不替换 A 卡**；离线 AUC 记录，A 卡 **≥ 约 0.714**。  
3. 模型/规则管理 API：列表、激活、回滚（给 Vue 模型页）。  
4. 反欺诈案件 **落库**（可与刘的预警表对接，但处置 API 在风控服务）。  
5. 修正管理端 A 分档阈值（按 788/642 或 PDO 分位，禁止再用 80/60）。  
6. 本服务单元测试：黑名单矩阵、决策函数、规则缺失兜底。  
7. 提供给刘的内部接口：`userId → 是否可支用 / 最新 A/B 分 / 预警信号`（Feign/HTTP，禁止刘直连征信库）。

**个人验收（中期、终期他必须自己点）**

- Postman：高分通过、低分拒绝、黑名单拒绝、复核+补充材料。  
- 切换辅助模型开关，决策结果可解释。  
- 出示 A 卡训练日志，AUC 不低于综设 II。  
- 至少 10 个本模块 JUnit。  

**他不做什么**：产品表、催收工单、客服、网关。前端找他只要风控接口挂了。

### 2.2 后端乙 · 刘：信贷账务服务（`loan-service`）

**为什么给他**：业务状态机新、表新、演示路径最长，**没法用「我在写报告」代替**；也不依赖把评分卡公式搞懂。

**迁入（已有）**

- `LoanController` / `RepaymentController`  
- 管理员借款审批、还款查询、逾期列表  
- `RepaymentScheduleTask`、`OverdueLimitAdjustTask`（调额时调耿的 B 卡接口，不复制引擎）  

**本学期新做**

1. **消费贷产品**：`loan_product` 至少 2 条（消费贷必做 + 现金贷或循环额度）；申请/借款带 `productId`；利率期限额度从产品读，禁止写死同一套。  
2. 贷款状态机补全：放款 → 还款中 → 逾期 → **催收中** → 结清（可选核销）；顺手修正 `DISBURRSED`。  
3. **催收闭环**：逾期日检自动生成 `collection_case`；管理员登记催收动作（电话/邮件/承诺还款）；结清关案并释放额度。把现在的 `contactTimes=0` 假字段换成真数据。  
4. **贷中监控**：定时拉耿的 B 分 + 本服务逾期/使用率 → 写 `monitor_alert` → 观察/预警/降额（降额可复用已有调额日志）。  
5. 管理端 API：产品配置、监控列表、催收工作台（给徐）。  
6. 用户端 API：按产品申请、计划、还款（给曹）。  
7. 本服务测试：还款试算、逾期升级、催收状态迁移；构造「预期逾期 → 实际出催收单」数据。  

**个人验收**

- 演示账号 A：选消费贷 → 放款 → 还一期。  
- 演示账号 B：逾期 → 催收工单可填写结果 → 结清。  
- 演示账号 C：B 卡预警 → 管理端降额。  
- 两个产品利率/期限明显不同。  
- 本模块 JUnit + 一套 Postman 集合以他的名字提交。  

**他不做什么**：评分公式、大模型、网关。额度能不能批问耿的接口。

### 2.3 后端丙 · 陈：平台服务（`gateway` + `user-service` + `cs-service`）

**为什么给他**：几乎全是新代码，学网关/鉴权/大模型即可，**没有「看不懂老引擎所以没法动手」的借口**；客服不调第三方 API 整组直接差档。

**迁入（已有）**

- `AuthController`、`AdminAuthController`、JWT 签发  
- 用户/管理员 CRUD 可放 user-service  

**本学期新做**

1. **Spring Cloud Gateway + 注册中心**（Nacos 或 Eureka 二选一，文档写清）：路由到耿/刘/陈三个服务；统一 `/api/v1`。  
2. **鉴权与安全**：网关校验 JWT；**用户 Token 禁止访问 `/admin/**`**；限流；身份证/手机号脱敏；`operation_audit_log` 落库（登录、审批、调额、催收、工单）。系统配置改数据库，废除内存 `configStore`。  
3. **获客**：注册增加 `inviteCode`/`channel`；管理端漏斗（渠道 → 注册数 → 完件 → 通过），演示数据即可。  
4. **客服**：对话接口调用通义/DeepSeek 等；把 `model、requestId` 记入 `cs_message`；转人工生成 `cs_ticket`，管理端处理回写。敏感问题（为何被拒）走固定话术。  
5. Docker Compose：一键起 MySQL/Redis/三服务/网关（Python 训练可仍手动）。  
6. JMeter 脚本：登录 + 提交评估（经网关），出 P95/QPS 图——这是整组「高并发」的主要证据，挂在陈名下。  
7. 用户服务测试：越权访问管理接口必须 403；无 Token 401。  

**个人验收**

- 邀请码注册，管理端能看到该渠道。  
- 客服问「怎么还款」有大模型回复，日志能证明不是本地 if-else。  
- 转人工工单管理员能关。  
- 普通用户 Token 打审批接口失败。  
- Compose 能起网关，徐/曹只配一个 baseUrl。  

**他不做什么**：评分、借款状态机。网关挂了算他的，不算耿刘的。

## 3. 防摸鱼规则（写进组约定，答辩用 Git 说话）

1. **目录所有权**：除公共 DTO 外，禁止改别人 `services/*` 里的业务代码；要改就提 Issue/PR，由主人合并。  
2. **每周最低证据**：每人至少 1 次有效提交（能编译的接口或测试），周日晚上发：接口列表 + 自测截图。连续两周零提交，该模块按未完成计。  
3. **中期个人演示 8 分钟**：只演示自己服务，老师/组长按第 2 节验收清单打勾。演示不了 = 该同学本阶段未完成，不能用「我们一起做的」糊弄。  
4. **接口冻结日**：W6 前三人把 OpenAPI 初稿交给徐/曹；之后改字段必须通知前端。前端联调失败先查是谁的服务 5xx。  
5. **文档跟代码走**：刘写 `loan-service` 详细设计+催收测试数据预测表；陈写网关/安全/客服设计+压测；耿写决策中枢与模型对比。中期/终期报告里 **禁止刘陈只写摘要和致谢**。  
6. **终期 Git**：`git shortlog -sn` 和各人 `git log --author` 截图进报告第四章。  

徐、曹不是后端，但：**没有对应后端接口时，前端做假页面不算该扩展已完成。**
