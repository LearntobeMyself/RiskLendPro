# 贷款产品需求分析

评分通过后，用户得到一条可循环的信用额度。产品是后来加上的借款入口，分成四种，挂在平台自己的分类下，不做法机构验资。

演示数据用 `docs/seed-catalog/演示产品目录.md` 里的 12 个产品。目录中的银行、消金公司只是文案，不作为业务对象。代码里的 `loan_institution` 保留现状，本需求不再扩展。

本期不做：逾期、催收、B 卡调额、先息后本、等额本金、随借随还、提前结清。

---

## 1. 两种额度

| | 信用额度 | 抵押额度 |
|---|---|---|
| 谁用 | 个人信用贷、消费分期、经营贷、不选产品直接借 | 只有房抵、车抵 |
| 上限 | 剩余信用额度，并且落在产品额度区间内 | 评估价 × 抵押率，再和产品额度区间取交集。住宅最高 70%，车辆最高 80% |
| 超过上限 | 直接拒绝，管理员不能改成通过 | 按抵押率封顶，不看剩余信用额度 |
| 放款 | 金额合格就直接发放，并扣减剩余额度 | 材料齐全后进入等待审批，管理员确认抵押物再放款 |
| 还款 | 等额本息。还回的本金恢复信用额度 | 等额本息。不占用、不恢复信用额度 |

经营贷即使勾了「可选抵押」，仍然走信用额度。

当前代码把「超过剩余额度」送进管理员审批。对信用类产品，这与上表相反，记为待改。

## 2. 四种分类

分类固定，管理员不能新建、改名或删除。某个分类要能被申请，就必须在该分类下新建产品。

| 代码 | 名称 | 演示产品 | 抵押 |
|---|---|---|---|
| PERSONAL_CREDIT | 个人信用贷 | 薪金闪贷、随心周转金、公积金专享贷、公职优待贷 | 只能填「无需抵押」 |
| BUSINESS | 企业经营贷 | 经营周转贷、个体商户快贷 | 「无需抵押」或「可选」 |
| MORTGAGE | 抵押贷款 | 安居房抵贷、途安车抵贷 | 只能填「需要抵押」，并写明房产或车辆 |
| CONSUMER_INSTALLMENT | 消费分期 | 安心家装分期、学途教育分期、智选数码分期、暑期消费专项 | 只能填「无需抵押」 |

车贷 = 抵押贷款且抵押物为车辆，演示产品是途安车抵贷。房抵 = 安居房抵贷。

## 3. 管理员维护产品

管理员负责新建、编辑、上架、下架。用户只看已上架产品。

新建必填：名称、分类、摘要、封面、额度上下限、期限上下限、期限单位、年化上下限、还款方式、是否抵押、数据来源、核对日期。

数值约束：上限不小于下限；利率不为负，年化不超过 24%；期限单位为月。房抵材料至少有房产证。车抵材料至少有行驶证和车辆登记证。适用人群含特定身份时，材料清单必须带上第 4 节对应的证明，否则不能保存。

查重：

- 名称去掉首尾空格后，全平台不能与另一条产品相同。
- 同一分类内，额度区间、期限区间、年化区间、还款方式集合完全相同，名称不同也拒绝。
- 薪金闪贷和随心周转金额度有重叠，但区间和还款方式不同，允许共存。
- 编辑时用同一规则，不和自己比较。

上下架：

- 还款方式不含等额本息，不能上架。
- 已上架过的产品不能删除，只能下架。
- 下架后用户列表立即消失。已放款借据仍保留申请时的名称、利率和还款方式。

## 4. 用户申请

接口是 `POST /loan/request`，必须带产品编号。年龄取最近一次已通过评估的出生日期。

所有产品都先检查：

| 条件 | 结果 |
|---|---|
| 未登录 | 失败 |
| 未完成授信、授信未通过、命中黑名单、有逾期 | 失败 |
| 产品未上架 | 失败 |
| 年龄不在产品 `minAge`～`maxAge` | 失败。未写年龄限制的，只要求已满 18 岁 |
| 金额或期限越出产品区间 | 失败。刚好等于下限或上限，通过 |
| 还款方式不是等额本息，或不在产品支持列表里 | 失败 |
| 产品要求特定身份，但对应证明未上传 | 失败 |

特定身份和证明：

| 身份 | 演示产品 | 必须上传的证明 | 满足方式 |
|---|---|---|---|
| 工薪 | 薪金闪贷 | 近 6 个月工资流水，或社保缴纳证明 | 上传其中一种 |
| 公积金缴存 | 公积金专享贷 | 公积金缴存证明 | 必须上传 |
| 公职 | 公职优待贷 | 工作证或在职证明 | 上传其中一种 |
| 企业主 | 经营周转贷 | 营业执照 | 必须上传 |
| 个体工商户 | 个体商户快贷、经营周转贷 | 个体工商户营业执照 | 经营周转贷在「企业主」和「个体工商户」里证明一种即可 |

随心周转金写的是职业不限，不要求身份证明。有房、有车仍按抵押规则，不重复算作身份。

证明用 `POST /risk/assessment/supplement/upload` 上传。文件类型齐全后，信用类产品仍然直接发放，不因为要证明就改成人工审批。本期只检查证明是否上传，不鉴别真伪。

然后按额度类型：

| 类型 | 通过条件 | 结果 |
|---|---|---|
| 信用类、消费分期、经营贷、直接支用 | 产品下限 ≤ 金额 ≤ 剩余额度 | 直接发放，扣减剩余额度 |
| 同上 | 金额比剩余额度多 0.01 元，或剩余额度为 0 | 拒绝，原因「超出可用信用额度」 |
| 车贷 | `hasCar` 为 true，或已有确认过的车辆材料；且没有另一笔车贷处于等待审批 | 进入等待审批 |
| 房抵 | `hasHouse` 为 true，或已有确认过的房产材料；且没有另一笔房抵处于等待审批 | 进入等待审批 |
| 房抵、车抵 | 金额 ≤ min(评估价 × 抵押率, 产品上限)，且 ≥ 产品下限 | 管理员确认抵押物后放款 |

信用贷、消费分期不受房抵、车贷的「等待审批互斥」影响。该笔抵押申请被拒绝或已经发放后，可以再申请同一类。

补充材料上传复用 `POST /risk/assessment/supplement/upload`。这个接口目前只服务评估复核，挂到产品申请上尚未实现。

## 5. 还款

放款时按等额本息生成全部月供。用户一次还当期。全部还完，借据变为已还清。

只有扣过信用额度的借据，还回的本金才恢复剩余额度。利息不占额度。房抵、车抵的还款不改变信用额度。

提前结清、按日计息、先息后本本期不做。

## 6. 推荐

推荐只展示，不代替第 4 节的校验。关掉弹窗后，列表仍是全部已上架产品。

每条展示：封面、名称、分类、额度区间、年化区间、期限区间。最多 3 条。没有候选就不展示。

额度刚通过、信用额度已生成时弹一次。同一次授信不重复弹。候选要同时满足：

1. 已上架。
2. 年龄落在产品区间内。
3. 车贷或「有车人群」：`hasCar` 为 true。
4. 房抵或「有房人群」：`hasHouse` 为 true。
5. 走信用额度的产品：额度下限 ≤ 剩余额度。

按年化下限从低到高排序。需要特定身份的产品可以出现在弹窗里，卡片上写明还缺哪份证明。证明没上传时，点进去申请会失败。

例：22 岁、无房、无车、剩余额度 2 万，可推荐薪金闪贷（需工资流水或社保证明）和公职优待贷（需工作证或在职证明）；不推荐车抵、房抵。剩余额度只有 5 千时，不推荐下限 1 万的公积金专享贷。

同一产品累计成功放款满 2 笔时，在成功页再推荐最多 3 条。之后每满 2 笔再推一次。候选与上面第 2～5 条相同，并且必须是同一分类、不是当前产品。标签重合多的排前面。

`GET /loan/products/{productId}/similar` 只按分类和标签排序，不看借过几笔，不能当作本节省略实现。

## 7. 测试时用哪条产品

| 要验证的规则 | 产品 |
|---|---|
| 信用贷、无抵押、等额本息 | 薪金闪贷 |
| 同分类但区间不同，允许共存 | 薪金闪贷、随心周转金 |
| 同分类区间完全相同，拒绝保存 | 复制薪金闪贷的额度、期限、利率、还款方式 |
| 超过剩余额度必须拒绝 | 薪金闪贷 |
| 未上传工资流水或社保证明不能借 | 薪金闪贷 |
| 未上传工作证或在职证明不能借 | 公职优待贷 |
| 未上传公积金缴存证明不能借 | 公积金专享贷 |
| 未上传营业执照不能借 | 经营周转贷、个体商户快贷 |
| 可高于信用额度，不超过房价的 70% | 安居房抵贷 |
| 可高于信用额度，不超过车价的 80%；等待审批时不能再申请车贷 | 途安车抵贷 |
| 下架后用户看不到 | 暑期消费专项 |

现在就能对照代码执行的：列表只出现上架产品；金额和期限边界；未登录不能申请、不能保存产品；已上架过的产品不能删除；借据保存申请当时的名称和利率。

查重、两种额度、抵押材料、身份证明、推荐还没按本文件做完。执行结果与本文不一致时，写成「与需求不符」，不要写成通过。
