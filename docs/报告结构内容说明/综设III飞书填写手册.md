把本文粘进飞书文档「使用说明与组约定」。干活以 [综设III四阶段计划.md](./综设III四阶段计划.md) 为准。

**飞书需求表是给老师的作业。我们干活只看四个阶段，每人每阶段交一个能点的东西。点不出来就算没做完。**

旧编号 `G-W2-01` 作废。周任务只剩 20 行：`G-S1` … `A-S4`。

---

## 每天只做这件事

1. 打开 **周任务** → 视图「当前阶段」（现在是 **S1**）。
2. 只找 **自己那一行**（耿看 G-S1，刘看 L-S1，以此类推）。
3. 对照「当场能点什么」去做。做完：状态改 **已完成**，**证据链接**贴一个能打开的 URL。
4. 做不下去：状态改 **阻塞**，阻塞原因写成「等谁 + 等什么」。

不要从上扫到第 20 行以后的阶段。阶段没到，后面的行当目录。

## 状态和证据

| 状态 | 什么时候 | 必须同时有 |
|------|----------|------------|
| 未开始 | 默认 | 无 |
| 进行中 | 已经动手 | 最好先贴中间证据 |
| 已完成 | 「当场能点什么」都能打勾 | **证据链接不能空** |
| 阻塞 | 自己做不下去 | **阻塞原因点名等人或等接口** |

证据只贴 URL：Git 提交、飞书截图、Postman、录屏。不要写「见群里」「本地有」。

进展要写的话，加在「当场能点什么」末尾，不要删原文：

```
【进展 2026-09-15】
已做：……
还差：……
证据：https://……
```

## 需求列表：少改

用户故事、验收标准、角色、模块 **不要改**。  
阶段结束时：把对应 R 的状态改成已完成，补证据。  
讨论只追加 `【日期】结论：……`，不覆盖原来的字。

## 会议纪要：周日一行

新增一行，禁止写「大家同意继续开发」。

必须有：时间、到会人员、至少两个问号句、**至少两个姓名的不同观点**、结论（带 G-S1 / R03-1 这种编号）、未决（没有写「无」）、下一步 `@人 + 编号`。

记录人轮值：刘 → 陈 → 徐 → 曹 → 耿。

---

## 怎么 @

文件夹先分享给五个人（可编辑）。点开那一行 → 评论 → `@姓名`。只填负责人不一定会弹通知。

改了接口：到「接口归属」那一行评论 `@徐 @曹`。
