# RiskLendPro 测试开发策略

> 目标：将项目从“有部分单元测试的课程系统”提升为可用于测试开发面试答辩的质量工程项目。
>
> 基线日期：2026-10-12。

## 1. 当前基线

- 技术栈：Java 21、Spring Boot 3.5、Spring Cloud Gateway、OpenFeign、MyBatis-Plus、MySQL 双数据源、Redis、腾讯云 COS。
- 模块：`common-api`、`common-runtime`、`gateway`、`user-service`、`risk-service`、`loan-service`、`cs-service`。
- 主链路：注册登录 → A 卡风险评估 → 人工/自动授信 → 借款 → 还款/逾期 → B 卡贷后调额。
- 当前约有 16 个测试类、62 个 `@Test`，以 JUnit 5 + Mockito 单元测试为主。
- `mvnw.cmd test` 当前通过。
- 当前没有 Spring 上下文集成测试、Testcontainers、HTTP 切片测试、跨服务契约测试、CI 质量门禁和可重复性能基线。

## 2. 测试目标与核心不变量

测试不能只验证接口返回 200。以下不变量是本项目的质量核心：

1. 未授权用户不能读取或操作他人的评估、借款和还款数据。
2. 同一评估申请只能授信一次，重试不能造成额度重复累加。
3. `total_limit = used_limit + remaining_limit`，且三个值均不得小于零。
4. 同一期还款只能成功一次，并发请求不能重复释放额度。
5. 风险评估、贷款和还款只能进行合法状态跃迁。
6. 评分阈值必须以同一配置源为准，文档、代码、数据库规则和测试不能各自维护。
7. 跨服务调用失败后必须可重试、可对账或可补偿，不能留下“风控已通过但额度未到账”等永久中间态。
8. 定时任务和用户主动操作并发执行时，不能重复扣款、重复恢复额度或覆盖新状态。
9. 密钥、令牌、数据库和邮件凭据不能进入仓库或测试报告。

## 3. 已识别的主要质量风险

### P0：必须优先处理

| 风险 | 当前证据 | 可能后果 | 验证方式 |
|---|---|---|---|
| 评分阈值漂移 | 测试文档为 788/642，`RiskAssessmentServiceImpl` 和 `CreditScoreEngineImpl` 默认值为 720/580 | 错放、错拒，测试结论与产品规则冲突 | 788、787、642、641 四个边界测试；收口为单一配置源 |
| 授信跨服务非原子 | 风控终态与贷款额度分属不同服务，本地事务无法覆盖 Feign | `FINAL_PASS` 但额度未到账，或重试后重复授信 | WireMock 模拟超时/500；验证幂等键、重试和对账 |
| 并发重复评估 | 业务层先查最新申请再插入，缺少可见的数据库唯一约束 | 同一用户产生两条进行中申请 | 并发集成测试 + 数据库约束检查 |
| 借款闸口缺少主链测试 | `getBorrowGate` 与 `requestLoan` 没有自动化主链覆盖 | 未授信/黑名单用户可能借款，或正常用户被误拒 | Service 单测、Controller 切片、Gateway 冒烟 |
| 认证和权限缺少 HTTP 测试 | 当前只测了路径角色矩阵，没有经过过滤器和 Security | 管理端越权、内部接口暴露 | MockMvc/WebTestClient 验证 401/403/200 |
| 还款与逾期任务竞态 | 主动还款加行锁，定时任务并发行为未被验证 | 状态覆盖、额度重复恢复、逾期金额错误 | Testcontainers 并发测试与账务不变量断言 |
| 仓库含默认敏感配置 | 共享配置存在数据库、Redis、邮件和内部令牌默认值 | 凭据泄漏、测试误连公网环境 | 立即轮换；测试配置必须 fail-closed |

### P1：P0 稳定后处理

- Feign 路径、字段和状态枚举缺少契约测试。
- `LoanCatalogService` 体量较大，目录上下架、缓存和 COS 上传主路径覆盖不足。
- 逾期、B 卡重算、黑名单同步等定时任务没有自动化验证。
- `user-service`、`gateway`、`cs-service` 当前没有测试类。
- Python 训练与 Java 在线评分结果缺少一致性测试。
- README、`start.bat` 和实际模块结构不一致，导致新环境无法按文档启动。

## 4. 分层测试方案

### L0：纯函数测试

保留并加强还款计算、DTO、状态枚举、规则解析等快速测试。

验收：

- 毫秒级执行。
- 必须覆盖空值、边界值、非法值和金额精度。
- 不连接 Spring、网络或数据库。

### L1：Service 单元测试

使用 JUnit 5 + Mockito 覆盖风险评估、借款闸口、借款、授信和还款编排。

验收：

- 断言业务异常类型/错误码，避免只断言 `RuntimeException`。
- 同时断言返回值、状态变化、Mapper 写入和外部调用次数。
- 对 Feign 超时、500、空响应分别验证。

### L2：Web 与 Security 切片测试

- MVC 服务使用 `@WebMvcTest` + MockMvc。
- Gateway 使用 `WebTestClient`。
- 覆盖用户、管理员、内部服务三类身份。

验收：

- 无令牌为 401。
- 角色不匹配为 403。
- 合法身份通过。
- 请求体校验、异常映射和 JSON 契约有断言。

### L3：数据库集成测试

使用 Testcontainers MySQL，不使用公网数据库，不优先使用 H2 模拟 MySQL 锁和 SQL 行为。

首批只做两条黄金链路：

1. 风险规则/黑名单 → 评估状态与报告。
2. 授信 → 借款 → 还款 → 额度恢复。

验收：

- 测试数据独立，可重复执行。
- 验证数据库最终状态及核心不变量。
- 覆盖事务回滚、唯一约束和 `FOR UPDATE` 并发行为。

### L4：跨服务契约测试

使用 WireMock 模拟 Feign 下游，验证路径、请求体、响应体、超时和错误处理。

不在第一阶段同时启动全部微服务；先用少量契约测试隔离失败原因。

### L5：Gateway 端到端冒烟

在稳定测试环境仅保留 3–5 条：

1. 登录获取 JWT。
2. 自动拒绝风险评估。
3. 自动/人工通过后授信。
4. 额度内借款。
5. 当期还款并恢复本金。

## 5. 首批 15 个高价值自动化用例

| 编号 | 目标 | 场景 | 预期 |
|---|---|---|---|
| P0-01 | `CreditScoreEngineImpl` | 三级黑名单命中 | 直接拒绝，不进入算分 |
| P0-02 | 评分边界 | 788/787/642/641 | 分别通过、人工、人工、拒绝 |
| P0-03 | `RiskAssessmentServiceImpl` | 正在处理的申请重复提交 | 只保留一条有效申请 |
| P0-04 | 自动授信 | 相同 `applyId` 重试两次 | 额度只增加一次 |
| P0-05 | 授信失败 | Feign 超时/500 | 状态可识别、可重试或可对账 |
| P0-06 | `getBorrowGate` | 未评估、拒绝、人工、通过 | 只有通过态允许借款 |
| P0-07 | 实时黑名单复检 | 已通过后进入黑名单 | 借款被拒绝 |
| P0-08 | `LoanServiceImpl` | 闸口拒绝 | 不写 Loan、不扣额度、不生成计划 |
| P0-09 | 额度内借款 | 合法金额与期限 | 放款、扣额、计划金额一致 |
| P0-10 | 并发借款 | 两笔请求竞争剩余额度 | 不超额、不出现负额度 |
| P0-11 | 并发还款 | 同一期同时提交两次 | 仅一次成功、仅释放一次本金 |
| P0-12 | 越权还款 | 用户操作他人计划 | 拒绝且无数据变化 |
| P0-13 | Gateway 权限 | USER 访问管理接口 | 403 |
| P0-14 | 内部接口权限 | 无内部 token 调额度接口 | 拒绝 |
| P0-15 | 定时任务竞态 | 逾期任务与主动还款并发 | 账务不变量与最终状态正确 |

## 6. 测试数据规范

- 测试用户、手机号、身份证号必须是专用虚构数据，不复用真实个人数据。
- 每个用例独立创建前置数据，禁止依赖执行顺序。
- 分数边界通过显式规则数据构造，不能依赖随机训练结果。
- 测试结束清理数据，或使用容器级隔离。
- 自动化测试不得连接默认公网数据库、Redis、COS、Coze 或真实邮件服务。
- 报告中隐藏 JWT、内部 token、手机号、身份证号、数据库地址和密码。

## 7. CI 质量门禁

建议按以下顺序落地：

1. `mvnw test`：每次提交执行快速单元测试。
2. `mvnw verify`：Pull Request 执行 `*IT` 集成测试。
3. 生成 JaCoCo 和 Allure 报告，但覆盖率只作为风险提示，不作为唯一质量指标。
4. 禁止真实环境凭据进入 CI；所有外部依赖使用容器、Mock 或空配置。
5. 单元测试失败、P0 集成测试失败、敏感信息扫描失败时阻断合并。

初始门禁建议：

- 已有测试必须全部通过。
- 新增/修改 P0 业务必须包含对应测试。
- P0 主链测试通过率 100%。
- 不允许新增明文密钥。
- 不允许测试访问公网业务数据库。

## 8. 性能测试最小方案

第一阶段只测两个场景：

1. 登录：验证认证服务与数据库连接基线。
2. 风险申请或借款：验证服务间调用、数据库、Redis 和外部依赖对延迟的影响。

必须记录：

- 请求模型、并发数、持续时间和测试数据规模。
- QPS、平均值、p95、p99、错误率。
- JVM CPU、堆、GC、线程。
- 数据库连接池、慢 SQL、锁等待。
- Redis 和下游 Feign 延迟。

报告必须包含环境、原始结果、瓶颈证据、优化方案和相同条件下的前后对比。

## 9. 面试项目故事

### 故事一：评分规则漂移治理

从“文档 788/642、代码 720/580”出发，建立单一配置源和边界自动化测试，解释为什么这是错放/错拒风险，而不只是代码常量问题。

### 故事二：跨服务授信幂等与补偿

围绕风控终态、额度授予、Feign 失败和重试，说明如何使用业务幂等键、对账和补偿避免重复授信与永久中间态。

### 故事三：并发借还款账务不变量

使用 Testcontainers MySQL 验证行锁、重复还款和定时任务竞态，始终断言额度与账务不变量。

## 10. 第一周学习与实施顺序

### Day 1

- 独立画出评估、授信、借款、还款调用链。
- 运行现有测试并阅读失败报告格式。
- 手写本文件第 2 节的核心不变量。

### Day 2

- 学习 JUnit 5、Mockito 的 Arrange-Act-Assert。
- 给评分阈值补 4 个边界测试。

### Day 3

- 给 `getBorrowGate` 补状态表驱动测试。
- 练习解释为什么 record/DTO 测试不能代替业务行为测试。

### Day 4

- 给 `LoanServiceImpl` 补闸口拒绝与额度内借款测试。
- 使用精确异常与交互次数断言。

### Day 5

- 学习 MockMvc/WebTestClient。
- 增加用户访问管理接口 403 和无 token 401 测试。

### Day 6

- 学习 Testcontainers MySQL。
- 搭建不连接公网的 `application-test.yml` 与首条数据库集成测试。

### Day 7

- 复盘发现的问题、测试证据和修复建议。
- 用 10 分钟完成一次项目答辩，回答“为什么先测这些，而不是追求覆盖所有接口”。

## 11. 完成定义

在简历写“建设自动化测试体系”前，至少满足：

- P0 15 个用例均已自动化并稳定运行。
- 至少 1 条数据库真实事务/并发集成测试。
- 至少 1 条 Gateway 权限测试。
- 至少 1 条 Feign 失败与恢复测试。
- CI 可在无真实密钥、无公网业务依赖下运行。
- 有一份可复现的性能报告。
- 有 5 个以上真实缺陷或设计风险闭环，全部有证据和回归测试。
- 能独立解释所有新增测试代码、失败原因、取舍和未覆盖风险。
