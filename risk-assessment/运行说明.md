## 四、执行顺序（请在 conda 环境中手动执行）

### 步骤 1：清洗外部特征样本（500 条）

```bash
conda activate 你的环境名
cd d:\javacode\RiskLendPro\risk-assessment
python clean_user_features.py
```

产出：`data/cleaned/cleaned_user_features.csv`  
记下其中任意一行的 **`id_card`**（18 位），联调注册/申请时需使用**相同身份证号**。

### 步骤 2：训练 HC 评分模型（读 parquet 全量）

```bash
python train_scoring_model.py
```

产出：`output/scoring_rules.json`  
检查：JSON 中 `model_type` 为 `hc_lr_standardized`，且 `feature_weights` 含 `ext_source_2` 等非零系数。

```bash
# 可选：快速查看权重
python -c "import json; r=json.load(open('output/scoring_rules.json',encoding='utf-8')); print(r.get('model_type')); print(r.get('feature_weights'))"
```

### 步骤 3：入库（建表 + 黑名单 + 外部特征 + 规则）

```bash
python load_to_mysql.py
```

**注意**：脚本会 `DROP` 后重建 `user_external_features`、`blacklist`，生产环境慎用。

### 步骤 4：启动 Java 后端

在 IDE 或命令行启动 Spring Boot 主类（`RiskLendPro` 应用模块）。  
确认 `application.yml` 中 credit 数据源指向 `credit_data_db`，且能加载 `scoring_rules` 表或 `output/scoring_rules.json`（按你项目现有配置）。

### 步骤 5：联调风控申请

1. 注册用户：`id_card` = 清洗 CSV 中某一行的 `id_card`（与入库 `user_external_features.id_card` 一致）。  
2. 提交风控评估：使用同一 `id_card`。  
3. 预期：能查到第三方特征；评分明细含 8 个 HC 特征；`ext_source_2` 等有贡献。

## 五、Java 调用逻辑说明（已修改部分）

### 5.1 `RiskAssessmentServiceImpl.submit` 顺序

1. 用户存在、身份证与请求一致、年龄 ≥ 18  
2. **黑名单** `checkBlacklist`（命中则直接拒绝/人工）  
3. **外部特征** `resolveExternalFeatures(idCard)` → **收入等验真** `verifyUserData`  
4. 重复申请检查  
5. **LR 评分** `getScoreDetailReport` / 写库决策  

### 5.2 `CreditScoreEngineImpl`（HC 模式）

- `resolveExternalFeatures`：先 `selectByIdCard`，再尝试 `selectBySkIdCurr`（纯数字联调）。  
- `buildHcRawFeatureMap`：3 个申请特征来自请求；5 个第三方特征**仅**来自 `UserExternalFeatures`。  
- `amt_income_total`：**不再**用外部后台收入覆盖 LR 输入（后台收入仅验真）。  
- `adjustLimitByExternalFeatures`：仅 `prev_refused_count` 额度惩罚，不对 `ext_source` 重复扣分。

### 5.3 `entity.credit` 包

| 类 | 对应表/用途 |
|----|------------|
| `UserExternalFeatures` | `user_external_features`（与清洗入库一致） |
| `Blacklist` | `blacklist` |
| `ScoringRules` | `scoring_rules` |

## 六、常见问题

| 问题 | 处理 |
|------|------|
| 外部特征全为 0 | 用户 `id_card` 与 CSV/库中 `id_card` 不一致；重新 `load_to_mysql` |
| **总分一直是 350** | 多为未命中 `user_external_features`，LR 把第三方当 0 入模 → 违约概率极高贴 `min_score=350`；见下方自检 SQL |
| **Redis 报告 externalFeatures 全 null** | 已改为 6.2 字段（`extSource2` 等）；需先命中第三方表 |
| `THIRD_PARTY_MISSING` / 人工无分数 | 正常保护：先入库再申请；`auditRemark` 会提示 |
| 训练走合成数据 | 确认 `data/raw/home_credit_train_min.parquet` 存在且含 `TARGET`、`DAYS_BIRTH` |
| `No module named 'pyarrow'` | `pip install pyarrow` |
| 表结构旧、缺 `id_card` | 重新执行 `python load_to_mysql.py`（会重建表） |
| 评分仍像 LC | 确认 `scoring_rules.json` 的 `model_type` 为 `hc_lr_standardized` |

### 6.1 第三方数据自检 SQL（与 Java 同一库）

在 MySQL 执行（将身份证号换成测试用例中的值）：

```sql
SELECT id_card, ext_source_2, ext_source_3, active_loans_count, credit_bureau_mon, amt_income_total
FROM credit_data_db.user_external_features
WHERE id_card = '110112199604210012';
```

- 有行且 `ext_source_2` > 0：Java 可正常 HC 评分，报告 `thirdPartyLinked=true`。
- 无行：申请会进入 `MANUAL_REVIEW`，`externalFeaturesMissing=true`，**不会**再出现误导性 350 分。

也可运行项目内脚本：`sql/verify_external_features.sql`（示例查询）。
