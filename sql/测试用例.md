# RiskLendPro 联调测试用例（v7.0-hc-woe）

## 0. 前置条件

> **重要**：[`clean_user_features.py`](../risk-assessment/clean_user_features.py) 每次重跑会**随机生成** `id_card` 中的月日。若你重新清洗 CSV，必须同步更新本文 `id_card` / `birthday`，或先运行 [`score_demo_users.py`](../risk-assessment/score_demo_users.py) 校准。

```text
1. cd risk-assessment
2. python clean_user_features.py      # 已完成可跳过
3. python train_scoring_model.py      # 生成 v7.0-hc-woe scoring_rules.json
4. python load_to_mysql.py            # DROP 重建表 + 500 条外部特征 + 激活规则
5. 双击仓库根目录 start.bat（或 mvnw.cmd -pl services/legacy-service spring-boot:run）
6. python score_demo_users.py           # 离线核对 PDO 分（输出 demo_user_scores.json）
7. 按用例：注册 → 登录 → POST /risk/submit（每例独立手机号）
```

| 项 | 当前值 |
|----|--------|
| 模型 | `v7.0-hc-woe`（WOE + LR + PDO） |
| 分数量表 | **350 – 950**（越高越安全） |
| 自动通过 | **≥ 788** |
| 人工审核 | **642 – 787** |
| 自动拒绝 | **< 642** |

管理员查看报告：`GET /admin/risk/report/{applyId}`（Redis 键 `risk:report:{applyId}`，TTL 1 天）。

> `mysql -u root -p risklendpro < sql/migration_b_card.sql`（或 Navicat 运行该文件），然后重启 Spring Boot。
> 验证：`SHOW COLUMNS FROM user_credit_limit LIKE 'b_%';` 应见 3 列。

```text
1. 已完成 B 卡训练与入库：train_b_card_model.py → clean_behavior_features.py → load_to_mysql 步骤6
2. 主库已执行 migration_b_card.sql（借款与 B 卡看板均依赖 user_credit_limit.b_* 列）
3. Spring Boot 已重启（加载 behavior_scoring_rules）
4. 演示用户需先完成：注册 → A 卡 submit → 管理员 PASS 授信 → 用户 POST /loan/request（额度内自动放款，不会重跑 A 卡评估）
```

管理员 B 卡看板：`GET /admin/b-card/monitor`（test-web 管理员页「5. B 卡贷后监控」）

手动重算 B 分（seed 改日期后）：`POST /admin/b-card/recalculate/{userId}`
