# 综设 III 四阶段计划（组员只看这一张）

旧的 100 条周任务（`G-W2-01` 那种）**作废**。干活只看四个阶段，每人每阶段交 **一个能当场点出来的结果**。点不出来就算没做完，不要靠任务编号报进度。

飞书「需求列表」24 条是给老师的作业，日常不当待办。对应关系见各行「关联需求」。

分工不变：耿管 gateway / user-service / risk-service；刘管 loan-service；陈管 cs-service；徐、曹只打网关。

```mermaid
flowchart LR
  S1["S1 中期前"] --> S2["S2 三条主路径"]
  S2 --> S3["S3 贷中贷后获客安全"]
  S3 --> S4["S4 联调测试答辩"]
```



编号：`G-S1` = 耿在阶段 1 的那一行。飞书「周任务」只保留这 20 行。

## 阶段 1 · 中期前：系统还在跑，服务能起

中期老师要看到：旧主流程没断，而且已经是多个进程，不是只改包名。


| 编号   | 人   | 交差时当场能点什么                                                              | 关联需求              |
| ---- | --- | ---------------------------------------------------------------------- | ----------------- |
| G-S1 | 耿   | `start.bat` 主流程还能走；gateway、user-service、risk-service 能单独起；经网关能登录、能提交评估 | R10-1、R03-1、R03-3 |
| L-S1 | 刘   | loan-service 能单独起；经网关用默认产品借一笔，利率从产品读，禁止写死 0.05                         | R05-1、R05-3       |
| C-S1 | 陈   | cs-service 能单独起；经网关 health 200；大模型 Key 已申请且不进 Git                      | （本阶段无需求闭环）        |
| X-S1 | 徐   | 管理端登录 + 待审批列表走网关，列表是真数据                                                | R03-2             |
| A-S1 | 曹   | 借款端登录 + 提交评估走网关，能看到进度                                                  | R10-1、R03-1       |


**本阶段禁止**

- 不要先做催收、工单、获客漏斗、压测。
- 不要为了拆服务把 `start.bat` 主流程拆断。断了先修，再谈新功能。
- 徐、曹不要直连 8081 等内部端口，只配一个网关地址。
- 陈不要用本地关键词冒充客服已通。本阶段只要求进程存活。

| 编号   | 人   | 交差时当场能点什么                                         | 关联需求                          |

| G-S2 | 耿   | 评估详情能讲清规则命中和 A 卡分；通过 / 复核 / 低分拒 / 黑名单拒四条能复现；模型页只读 | R01-1、R01-2、R02-1、R03-1、R03-4 |

| C-S2 | 陈   | 问「怎么还款」有第三方模型回复，库中有 model、requestId；「为何被拒」走固定话术   | R08-1                         |
