## 逾期等级与额度调整规则

### 1. 逾期等级定义

| 逾期等级 | 逾期天数   | 说明   |
| ---- | ------ | ---- |
| N    | 无逾期    | 正常状态 |
| M1   | 1-30天  | 轻度逾期 |
| M2   | 31-60天 | 中度逾期 |
| M3   | 61-90天 | 重度逾期 |
| M4   | 90天以上  | 严重逾期 |

### 2. 自动额度调整规则

系统每天凌晨2点会自动检查所有逾期用户，并根据逾期等级调整其信用额度：

| 逾期等级 | 调整后额度比例  | 调整原因      |
| ---- | -------- | --------- |
| M1   | 原额度的 80% | 轻度逾期，风险可控 |
| M2   | 原额度的 50% | 中度逾期，风险较高 |
| M3   | 原额度的 20% | 重度逾期，风险严重 |
| M4   | 额度清零     | 严重逾期，风险极高 |

### 3. 额度调整流程

1. **系统自动调整**：每日凌晨 2 点由 [`OverdueLimitAdjustTask`](../src/main/java/org/example/risklendpro/utils/OverdueLimitAdjustTask.java) 执行，**无对外 HTTP 调额接口**
2. **调整记录**：写入 `limit_adjust_log`（含调整前后额度、原因、操作人；定时任务 `operator_id` 为系统标识）

### 4. 逾期处理机制

- **还款提醒**：系统会在还款到期前3天、到期当天发送邮件提醒
- **逾期通知**：逾期第一天发送邮件通知用户
- **状态更新**：每日凌晨自动更新逾期状态和等级
- **额度影响**：逾期会直接影响用户的信用额度和借款资格

## 黑名单同步（永久 Token）

供**扣子平台工作流**或外部系统增量写入失信被执行人名单，**不使用** Admin JWT。

| 项 | 说明 |
|----|------|
| 完整路径 | `POST /api/v1/sync/blacklist` |
| 鉴权 | `Authorization: Bearer {api-token}` |
| Token 配置 | Java `application.yaml` → `risk.blacklist-sync.api-token` |
| 有效期 | 永久（静态 Token，非 JWT） |
| 写入库 | `credit_data_db.blacklist` |

该接口由 `JwtFilter` 单独校验静态 Token（路径后缀 `/sync/blacklist`），与登录 JWT 互不影响。

### 请求体（JSON）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | String | 是 | 被执行人姓名，支持 `*` 通配，最长 100 |
| `areaCode` | String | 否 | 地区编码，如 `110112` |
| `birthYear` | Integer | 否 | 出生年份，1900–当前年 |
| `caseNo` | String | 否 | 案号 |
| `courtName` | String | 否 | 执行法院 |
| `dutyStatus` | String | 否 | 履行情况，如「全部未履行」 |
| `behaviorDetails` | String | 否 | 失信行为描述 |
| `riskLevel` | String | 否 | `HIGH` / `MEDIUM` / `LOW`；未传则按 `dutyStatus` 推导 |

`createdAt`、`expireAt` 由服务端写入（`expireAt` 默认 NULL 永久有效）。

### 成功响应示例

```json
{
  "code": 200,
  "message": "黑名单写入成功",
  "success": true,
  "data": {
    "id": 203,
    "createdAt": "2026-06-05T12:00:00.000+00:00"
  }
}
```

### 错误说明

| code | 场景 |
|------|------|
| 401 | Token 缺失或不匹配 |
| 400 | `name` 为空、字段超长、`riskLevel` 非法、**该黑名单记录已存在** |

### 扣子工作流调用示例

```bash
curl -X POST "http://47.109.109.231:8080/api/v1/sync/blacklist" \
  -H "Authorization: Bearer {BLACKLIST_SYNC_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "孙*",
    "areaCode": "110112",
    "birthYear": 1986,
    "caseNo": "（2025）京0112执测L2号",
    "courtName": "北京市通州区人民法院",
    "dutyStatus": "全部未履行",
    "behaviorDetails": "有履行能力而拒不履行生效法律文书确定义务",
    "riskLevel": "HIGH"
  }'
```

**安全提示**：Token 以部署环境配置为准，扣子变量中引用 `BLACKLIST_SYNC_TOKEN`，勿在公开日志打印完整 Token。

### 扣子侧建议流程

1. Cron 定时（如每日 02:00）
2. HTTP 下载温州失信被执行人公开 CSV
3. 代码节点：复刻 `clean_blacklist.py` 字段映射
4. 循环 POST 本接口；400「已存在」视为跳过

详见 [`csv数据来源和数据库表设计.md`](csv数据来源和数据库表设计.md) 第七章、[`运行说明.md`](运行说明.md) 第九章。

## 二、授信评估模块 (Credit Assessment)

**核心逻辑**：用户提交申请 → Java 读取 `credit_data_db.user_external_features`（按 `id_card`）与黑名单 → **A 卡 WOE+LR+PDO**（`CreditScoreEngineImpl`，规则 `hc_woe_lr` v7）→ 规则门控（收入验真、黑名单 L2/L3 等）→ 写入 `risk_assessment`。

**PDO 决策阈值**（量表 350–950）：

| 分数 | 引擎建议 `sysDecision` | 典型业务状态 |
|------|------------------------|--------------|
| ≥ 788 | `APPROVE` | `FINAL_PASS`（无规则拦截时） |
| 642 – 787 | `MANUAL_REVIEW` | `MANUAL_REVIEW` |
| < 642 | `REJECT` | `SYSTEM_REJECT` |

离线模型训练在 `risk-assessment/`（`train_scoring_model.py` → `scoring_rules.json` → MySQL），**在线评分不调用 Python**。

**业务说明**：

- 客户端填写个人信息并提交
- 后端关联 Home Credit 模拟第三方特征、黑名单匹配
- 规则门控可强制人工（如黑名单 L2、收入异常）或补充材料
- 管理员对 `MANUAL_REVIEW` 订单终审；结果邮件通知用户

## 三、借款/支用模块 (Withdrawal/Loan)

**核心逻辑**:

- 用户发起借款时，系统首先检查借款金额与用户剩余额度的关系
- **额度内借款（金额 ≤ 剩余额度）**：系统自动审批通过，直接发放借款并扣减额度，无需管理员操作
- **额度外借款（金额 > 剩余额度）**：系统生成"贷款申请"记录，需要管理员审批后发放借款，审批通过后邮件通知用户

**业务状态码说明（借款模块）**:

| 借款状态码             | 说明               |
| ----------------- | ---------------- |
| PENDING\_APPROVAL | 待审批（额度外借款需管理员审批） |
| APPROVED          | 已审批通过            |
| REJECTED          | 审批拒绝             |
| DISBURRSED        | 已发放              |
| REPAID            | 已还清              |
| OVERDUE           | 逾期中              |

### 3.1 发起借款请求

- **URL**: `/loan/request`
- **方式**: POST
- **Content-Type**: application/json
- **描述**: 用户输入"借款金额"和"还款期限"，系统判断借款金额与用户剩余额度的关系

**业务逻辑**:

```
用户发起借款
    ↓
检查用户是否有未处理逾期
    ↓
检查借款金额 vs 剩余额度
    ↓
├── 金额 ≤ 额度 → 自动审批通过 → 状态变为 DISBURRSED → 扣减额度 → 直接放款
└── 金额 > 额度 → 状态变为 PENDING_APPROVAL → 等待管理员审批
```

| termMonths      | Integer    | 是  | 还款期限（月）              |
| repaymentMethod | String     | 是  | 还款方式（等额本息/等额本金/先息后本） |

### 6.9 B 卡贷后监控

- **鉴权**: Admin JWT

| 字段 | 说明 |
|------|------|

### 6.10 手动重算 B 卡

- **鉴权**: Admin JWT

