# RiskLendPro — Home Credit 评分卡运行说明（Conda 环境）

本文档说明在 **Conda** 下完成数据清洗、A/B 卡模型训练、MySQL 入库、Java 联调，以及**扣子平台定时同步黑名单**的完整步骤。

字段定义见 [`csv数据来源和数据库表设计.md`](csv数据来源和数据库表设计.md)，A 卡原理见 [`HomeCredit评分卡使用说明.md`](HomeCredit评分卡使用说明.md)。

## 四、离线执行顺序

### 步骤 1：清洗数据

```bash
python clean_blacklist.py          # → data/cleaned/cleaned_blacklist.csv
python clean_user_features.py      # → data/cleaned/cleaned_user_features.csv
python clean_behavior_features.py  # → data/cleaned/cleaned_behavior_features.csv（B 卡）
```

联调时记下 `cleaned_user_features.csv` 中某一行的 **`id_card`**，注册/申请须一致。

### 步骤 2：训练模型

```bash
python train_scoring_model.py   # A 卡 → output/scoring_rules.json
python train_b_card_model.py    # B 卡 → output/b_scoring_rules.json
```

A 卡检查：`model_type` = `hc_lr_standardized`，`feature_weights` 含非零 `ext_source_2`。

### 步骤 3：入库

```bash
python load_to_mysql.py
```

依次：建库建表 → 黑名单 → 用户特征 → A 卡规则 → B 卡特征与规则。

**注意**：A 卡相关表（含 `blacklist`、`user_external_features`）会 **DROP 后重建**，生产环境慎用全量脚本。

### 步骤 4（可选）：校准测试用例分数

```bash
python score_demo_users.py   # → output/demo_user_scores.json
```

供 [`../sql/测试用例.md`](../sql/测试用例.md) 对照。

### 步骤 5：启动 Java 并联调

1. 启动 Spring Boot（`context-path: /api/v1`）
2. 注册用户：`id_card` 与 CSV 一致
3. 提交 `POST /api/v1/risk/assessment/submit`
4. 预期：第三方特征命中、PDO 分 350–950、黑名单三道匹配

## 五、Java 调用逻辑摘要

### 5.1 A 卡 `RiskAssessmentServiceImpl.submit` 顺序

1. 准入（用户、身份证、年龄 ≥ 18）
2. **黑名单** `checkBlacklist`（L3 拒绝 / L2 强制人工）
3. **外部特征** + **收入验真**
4. 重复申请检查
5. **LR+PDO 评分**（无第三方 → 人工不算分）

### 5.2 B 卡

- 实体：`UserBehaviorFeatures`、`BehaviorScoringRules`
- 引擎：`BehaviorScoreEngine` / `BehaviorScoreService`
- 借款时读取 `user_behavior_features.feature_json` 与 B 卡规则

### 5.3 `entity.credit` 包

| 类 | 表 |
|----|-----|
| `UserExternalFeatures` | `user_external_features` |
| `ScoringRules` | `scoring_rules` |
| `Blacklist` | `blacklist` |
| `UserBehaviorFeatures` | `user_behavior_features` |
| `BehaviorScoringRules` | `behavior_scoring_rules` |

## 六、常见问题

| 问题 | 处理 |
|------|------|
| 外部特征全 0 / 350 分 | `id_card` 与库不一致；重跑 `load_to_mysql` |
| `THIRD_PARTY_MISSING` | 先入库再申请 |
| 训练走合成数据 | 确认 parquet 存在 |
| B 卡表空 | 先 `clean_behavior_features` + `train_b_card_model` |
| 黑名单未更新 | 全量：`load_to_mysql`；增量：检查扣子工作流与 sync Token |

## 八、黑名单入库两种方式

| 方式 | 场景 | 步骤 | 是否 DROP 表 |
|------|------|------|-------------|
| **A 全量** | 开发、首次部署、重导测试数据 | `clean_blacklist.py` → `load_to_mysql.py` | 是 |
| **B 增量** | 生产定时拉取最新失信名单 | 扣子工作流 → `POST /api/v1/sync/blacklist` | 否 |

方式 B 适合日常更新；方式 A 适合环境初始化或与 CSV 完全对齐。

## 九、扣子工作流配置清单

### 9.1 流程概览

1. **Cron 触发**（建议每日 02:00）
2. **HTTP 下载** [温州失信被执行人公开 CSV](https://data.wenzhou.gov.cn/jdop_front/detail/data.do?iid=13341)
3. **代码节点**：字段映射（同 `clean_blacklist.py`）
   - 法院名 → `areaCode`
   - 出生日期 → `birthYear`（前 4 位）
   - 履行情况 → `riskLevel`（可选，也可由 Java 推导）
4. **循环 + HTTP POST** 每条记录到 Spring Boot

### 9.2 扣子环境变量

| 变量 | 说明 |
|------|------|
| `SPRING_BASE_URL` | 如 `http://47.109.109.231:8080` |
| `BLACKLIST_SYNC_TOKEN` | 与 Java `risk.blacklist-sync.api-token` 相同 |

### 9.3 调用示例

```bash
curl -X POST "{SPRING_BASE_URL}/api/v1/sync/blacklist" \
  -H "Authorization: Bearer {BLACKLIST_SYNC_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"name":"吴*微","areaCode":"110112","birthYear":1977,"dutyStatus":"全部未履行"}'
```

### 9.4 响应与错误

| HTTP | 含义 | 扣子侧处理 |
|------|------|-----------|
| 200 | 写入成功，返回 `id`、`createdAt` | 计数 +1 |
| 400 | 校验失败或「该黑名单记录已存在」 | 重复可跳过 |
| 401 | Token 无效 | 告警，停止任务 |
| 5xx | 服务异常 | 重试或告警 |

详细字段见 [`接口文档.md`](接口文档.md)「黑名单同步」章节。
